# 正式工具接入窗口跨显示器移动

## 问题与依据

用户在 macOS 26.6.2 上测试 FinderSpaceDemo 0.2（#98，bd814c3）后反馈“测试成功，按这个实现功能”。正式工具目前仅提交 Space 移动请求，没有将窗口放置到目标显示器，也在 Shelf 已取键盘焦点后才读取原窗口。

## 变更

- Shelf 进入键盘会话前固定原应用、AXWindow 和 Window ID；桌面菜单展示源应用名称。
- 接入 Demo 的 Objective-C 请求桥接和 AX 跨屏放置。保留点尺寸，窗口大于目标可见区域时按需缩小。
- 跨屏先确认目标屏放置，再请求指定普通 Space；连续三次同时确认唯一目标 Space 和完整窗口位置后才成功。
- 菜单保留普通切换、⌥ 移动、⌥⇧ 移动并跟随；增加无需修饰键的两个移动子菜单，标注目标显示器编号/名称。
- 以真实 Space ID 和显示器标识绑定目标，桌面重排不会误操作另一个桌面；显示器变化、全屏/分屏、多 Space、失效窗口等明确失败。
- 桌面动作接管后取消 Shelf 延迟恢复旧焦点。跟随只聚焦原窗口，鼠标放到该窗口可见区域；并发桌面动作串行执行。

## 验证边界

用户已经确认 Demo 测试成功，但没有提供具体调用方式、完整场景矩阵或日志，不扩展为所有 App 和布局已验证。正式 App 的快捷面板捕获、菜单、跨屏/跨桌面组合与焦点恢复仍需按 VERIFY_ON_MAC.md 在用户 Mac 回归。

CI 覆盖坐标计算和联合确认状态序列、Swift 编译、生产 Objective-C 桥接的自有窗口同 Space 调用及正式 App 签名打包；不以 CI 代替真实外部窗口移动验收。
