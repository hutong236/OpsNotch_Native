# shelf-performance Specification

## Purpose

约束 Shelf 的触发响应、存储增长与持久化行为:Sensor 触发路径不被存储磁盘 I/O 阻塞,重复捕获的内容上浮而非无限累积,条目规模有界,持久化按需写盘且始终保持 legacy 数据兼容。

## Requirements

### Requirement: Sensor 触发路径不得被存储磁盘 I/O 阻塞

从鼠标(或拖拽)进入 Sensor 到抽屉开始显示的主线程路径上,系统 MUST NOT 同步执行存储文件的读取或写入。列表数据以内存状态为权威,仅在应用启动或用户显式触发刷新时从磁盘加载。

#### Scenario: 大数据量下悬停触发

- **WHEN** 存储中已有 300 条以上条目,用户鼠标移入 Sensor 触发展开
- **THEN** 展开过程不在主线程同步读写存储文件,面板按既定的拖拽优先延迟及时出现,无不因存储 I/O 产生的额外停顿

#### Scenario: 反复触发不产生磁盘写入

- **WHEN** 数据未变化的情况下用户反复进出 Sensor 触发展开与收起
- **THEN** 存储文件的内容与修改时间不因这些触发而改变

### Requirement: 一次剪贴板捕获只做一趟存储操作

剪贴板自动捕获文本时,系统 SHALL 在单次存储操作内完成"相同内容判定与上浮(或新增)",并以该次结果直接刷新界面;同一次捕获 MUST NOT 重复读取存储文件,也不得因界面刷新而再次读写存储文件。

#### Scenario: 捕获新文本

- **WHEN** 用户复制一段当前不存在的新文本
- **THEN** Recent 分区出现该条目,整个过程只发生一次存储文件读取与一次存储文件写入

#### Scenario: 捕获已存在的文本

- **WHEN** 用户复制一段与现有文本条目内容相同的文本
- **THEN** 不新增条目,已有条目上浮至 Recent 顶部

### Requirement: 拖入内容与剪贴板捕获采用一致的去重语义

通过 Sensor 拖入的文本与 http/https URL,若与现有条目内容相同,SHALL 上浮已有条目而非新增重复条目。用户在编辑器中手动新建的条目不受此限制,仍允许内容相同但标题不同的多个条目并存。

#### Scenario: 重复拖入相同文本

- **WHEN** 用户先后两次拖入完全相同的文本内容
- **THEN** 列表中只有一条该文本条目,且其最近使用时间被刷新

#### Scenario: 拖入已存在的 URL

- **WHEN** 用户拖入一个与现有条目相同的 http/https URL
- **THEN** 不产生重复条目,已有 URL 条目上浮

#### Scenario: 手动新建不受去重限制

- **WHEN** 用户通过"添加文本"手动创建与现有条目内容相同的条目
- **THEN** 系统正常创建新条目,不执行去重

### Requirement: 条目总数有软上限且淘汰保护置顶与 Working Set

存储 SHALL 将条目总数限制在上限内(500 条)。新增导致超限时,系统 MUST 淘汰"最近更新时间最旧、未置顶且不在 Working Set 中"的条目;置顶条目与 Working Set 条目 MUST NOT 被自动淘汰。

#### Scenario: 超限淘汰最旧的未保护条目

- **WHEN** 条目数达到上限后继续捕获新内容,且存在未置顶、不在 Working Set 的旧条目
- **THEN** 最旧的一条未置顶且不在 Working Set 的条目被移除,总数保持不超过上限

#### Scenario: 置顶与 Working Set 条目豁免

- **WHEN** 淘汰发生时,按更新时间排序的最旧条目实际处于置顶或 Working Set 状态
- **THEN** 该条目被跳过,淘汰落到下一个符合条件的条目

### Requirement: 持久化按需写盘且保持 legacy 兼容

存储加载 SHALL 为无副作用操作:仅当解码后实际发生格式迁移或 TTL 过期清理时才写回存储文件。数据格式与 legacy V0.x/V1.x 根数组格式的迁移兼容性 MUST 保持,写出的文件 MUST 仍为可正常解析的标准 JSON。

#### Scenario: 无变化的读取不写盘

- **WHEN** 存储文件无待迁移数据、无过期条目,应用读取它
- **THEN** 存储文件不被改写

#### Scenario: legacy 迁移时写盘

- **WHEN** 应用读取 legacy 根数组格式的存储文件
- **THEN** 数据被迁移为当前格式并写回,条目内容保持一致

### Requirement: 性能优化不改变展示排序语义

存储与排序相关的性能优化 MUST NOT 改变列表的可见排序规则:查询匹配优先级、时间衰减、使用频率与环境上下文加成的相对影响保持现状。

#### Scenario: 排序结果等价

- **WHEN** 同一组条目在优化前后以相同的查询、筛选与环境上下文计算展示排序
- **THEN** 两次输出的顺序完全一致
